# MORI iOS 시뮬레이터 QA — 2026-11-06

## 판정
원문 기반 병원 탐색 → 방문 준비표 저장 → PDF 파일 저장 경로는 시뮬레이터에서 시연 가능하다. 제품 출시/실제 번역/의료진 활용 검증 완료라는 의미는 아니다. 기능 추가 없이 현행 구현을 검사했다.

## 환경과 방법
- 기준 코드: cb3ea254ae6aa92e981d2699236499891d82d6d0, main.
- Flutter 최신 소스로 iOS simulator build 성공. iPhone 16e / iOS 26.2.
- API_URL=http://localhost:8791. 별도 Node 서버와 /tmp/mori-qa-20261106.sqlite 사용. 실제 사용자 DB와 분리.
- QA 환경은 .env를 로딩하지 않아 AI/지도 키 없는 상태. 이 결과만으로 다른 배포 환경의 키 유무를 단정하지 않는다.
- 가상 계정은 로컬 API로 생성하고 UI로 로그인. 회원가입 UI 자체는 이번 검증 범위가 아니다.
- 테스트 입력: TEST ONLY: sore throat and cough / 2 days ago / Worse today / pain 4. 약·알레르기 미입력.

SQLite 직접 검사에서도 symptoms에 원문+증상 변화가 보존되고, onset='2 days ago', painScore=4, 약/알레르기 unknown임을 확인했다. PDF 파일 본문 텍스트 자동 추출 도구가 환경에 없어 파일 헤더/크기 및 앱 미리보기 시각 점검을 근거로 삼았다. 실물 iPhone에 저장한 것은 아니다.

## 발견 사항 / 다음 작업
1. **P0 실제 번역 검증 미완료**: 사용자 소유 설정으로 가상 사례 실호출→대조→확인→PDF 필요. 현재 원문 데모와 구분할 것.
2. **P1 최초 로그인 때 긴급 개인정보 화면이 먼저 열림**: 뒤로 가면 선택한 병원과 준비 화면으로 돌아오지만 핵심 경로를 중단한다. 선택/건너뛰기를 명확하게 할 것.
3. **P1 병원 선택 안내**: ENT 목록에 등록 진료과는 있지만 ENT 전문의 0명인 기관도 포함된다. 현재 수치는 표시하지만 사용자가 이를 전문의 추천으로 오인할 수 있다. 전문의 필터/정렬과 등록 진료과 설명을 검토할 것.
4. **P1 영어 사용자 접근성**: 영문 UI에서도 기관명·주소·종별 일부는 한국어. 한국어 주소 보존과 별개로 영문 안내 보강 필요.
5. **P1 화면 정보 우선순위**: 방문 준비 상단에 접속자 그룹 UI가 크게 노출된다. 입력에 도달하기까지 스크롤 부담을 줄일 필요가 있다.
6. **P2 문구**: 한국어 홈 컨디션에 raw unknown 표시, PDF 미기록 체온에도 °C가 붙는다. 정상 수치로 바뀌지는 않지만 마감 전 문구 정리 권장.
7. 선택 병원은 현재 세션용이다. 재실행 후 병원 예약/카드 병원 필드 영구 저장을 보장하지 않는다.

자동 입력 중 macOS/iOS 입력기 영향으로 문자열이 누락/한글 자모화되었다. 영문 전환 및 키 단위 입력으로 복구했고 최종 값을 화면/DB에서 대조했다. 앱 인증 실패로 판정하지 않는다.
