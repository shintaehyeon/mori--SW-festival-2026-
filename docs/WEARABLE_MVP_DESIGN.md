# MORI 웨어러블 MVP 설계

설계일: 2026-11-03. 사용자 요청에 따른 설계안이며 아래 기능 전체의 구현 완료를 뜻하지 않는다.

## 제품 목표와 범위
외국인 이용자가 병원에 방문할 때 최근 건강 기록을 직접 확인하고, 필요한 요약만 의료진에게 보여주는 준비표에 첨부한다. 워치 앱을 새로 만들지 않고 iOS HealthKit / Android Health Connect를 읽는다. 심박수·수면·걸음 수만 지원한다. 실시간 감시, 응급 판정, 건강 점수, 이상 알림, 자동 신고, AI 해석, 가족 자동 공유는 MVP에서 제외한다.

## 이용 흐름
일반 진료 → 방문 준비표 → 선택 기능 ‘건강 앱에서 기록 가져오기’ → 세 항목 중 읽을 항목 선택 → 간단한 목적/보유 안내 및 필요한 동의 → OS 읽기 권한 → 결과 3장 → 준비표에 포함할 항목 체크(기본 미선택) → 첨부 미리보기 → PDF 저장/사용자가 의료진에게 제시.
거부·무자료·워치 미보유여도 수동 입력 준비표를 계속 이용한다. 로그인 없는 긴급 도움을 건강 권한이나 설정 화면으로 막지 않는다. 웹에는 네이티브 앱에서 사용 가능하다는 안내만 표시한다.

## 표시할 세 가지 요약
| 항목 | MVP 표시 | 조회·계산 기준 |
|---|---|---|
| 심박수 | 최근 기록 1개 bpm, 실제 측정 시각, 출처, 조회 시각 | 최근 24시간 중 최신의 유효 기록. 현재 실시간 맥박이나 안정시 심박으로 재해석하지 않음. 평균·최고·최저와 정상 판정 제외 |
| 수면 | 최근 수면 구간의 시작/종료·실제 수면 합계, 출처 | 최근 72시간에서 선택 출처의 최신 종료 수면 구간. 실제 수면 단계만 합집합으로 병합하여 중복 제거. 깨어 있음·침대에 있던 시간 제외. 상위 asleep 기록과 light/deep/REM을 중복 합산하지 않음. 기록 연속성을 확인할 수 없으면 밤 전체 수면으로 묶지 않고 구간별 표시 |
| 걸음 수 | 오늘 기록된 걸음 수, 집계 시작/종료·시간대·출처 | 기기 현지 날짜 00:00~조회 시점. OS의 중복 제거 집계가 플러그인에서 보장되는지 확인 후 사용. 그렇지 않으면 사용자 선택 출처 하나만 집계. 휴대폰+워치 원시값 단순 합산 금지 |

각 카드에 측정/집계 기간과 앱 조회시각을 분리해 표시한다. 실제 반환된 원본 앱·기기 정보를 표시하며 기기 모델이 없으면 ‘기기 미제공’으로 남긴다. Samsung Health라는 출처명만으로 Galaxy Watch 측정이라고 확정하지 않는다. 데이터 없음은 ‘읽을 수 있는 기록 없음’이며 0·정상·권한 거부로 단정하지 않는다. 날짜와 시간대를 함께 보존해 여행 중 날짜 변경을 설명할 수 있게 한다. 갱신은 명시적 버튼으로만 수행한다.

## 출처·중복·부분 실패
OS adapter → 타입별 정규화 → source/원본 ID 기반 중복 제거 → 항목별 요약 → 미리보기 모델 순으로 구성한다. 각 항목은 independent 상태(idle/loading/available/noReadableData/error/unsupported)를 가진다. 한 항목 실패로 다른 결과를 없애지 않는다. 심박·수면·걸음마다 출처를 따로 고를 수 있다. 수동 입력은 기기 기록과 별도 표기한다. 비정상 형식·NaN·음수·역전 시간·조회 범위 밖 자료는 제외하고 제외 여부를 기록한다. 생리적 정상 범위나 진단 규칙은 추가하지 않는다.

## 준비표와 보관: MVP는 로컬 첨부
기존 서버 카드에는 워치 데이터를 추가하지 않는다. 준비표 화면에서 사용자가 선택한 summary snapshot만 로컬 메모리로 전달해 미리보기/PDF에 포함한다. 표시 문구: ‘이번 준비표·PDF에만 포함됩니다. 계정에는 저장되지 않습니다.’ 저장된 카드 재열기 시 첨부가 없다는 점을 명시하고 다시 가져오기를 제공한다.
요약 선택 후에는 불변 사본으로 고정한다. 배경 갱신이나 새로운 원본으로 PDF 내용이 저절로 바뀌지 않는다. 건강 화면을 닫으면 raw samples를 지우되 사용자가 명시적으로 첨부한 요약은 준비표 화면 수명까지 유지한다. 준비표 종료·로그아웃·읽기 중단 시 관련 메모리 첨부도 폐기한다. 이미 내보낸 PDF는 앱 메모리 삭제로 지워지지 않는다고 알린다. OS 원본과 OS 권한은 앱 화면 지우기와 별개다.

## 요약 모델
WearableSummary: kind, value, unit, intervalStart, intervalEnd, timezoneOffset, sourceApp, sourceDevice?(실제 제공될 때만), sourceId(내부용), readAt, aggregationMethod, completenessNote.
VisitWearableAttachment: selectedSummaries, selectedAt, consentVersion. 원본 ID는 표시/PDF에서 제외한다. health record 원시값·위치·계정 ID는 첨부 모델에 넣지 않는다. 서버/AI 요청 모델에서 이 모델을 제외한다. 화면 결과는 진료기록이 아니라 ‘사용자가 선택한 건강 앱 기록’으로 구분한다.

## 권한과 UX
전경 READ 권한만, 항목별 최소 요청. 모두 동의/백그라운드/쓰기 권한 없음. 앱 내 동의와 OS 권한은 별도 단계다. 동의 화면의 긴 설명은 상세보기로 두고 첫 화면에는 항목·목적·기기 내 처리·선택 첨부를 설명한다. 현재 ‘화면 종료 시 모두 삭제’ 문구는 명시적 요약 첨부 수명과 PDF 반출을 설명하도록 구현과 함께 수정해야 한다. 위치 기반 병원 찾기의 권한/데이터는 본 기능과 결합하지 않는다.

## 구현 순서
1. existing reader 확장: 걸음 수, 수면 단계별 조회, 원본 앱·가능한 기기 정보.
2. 출처 선택·중복 처리·세 가지 요약 pure function 및 가상 fixture 검사.
3. 결과 3장과 항목별 실패/무자료·선택 UX.
4. 로컬 준비표 첨부 snapshot과 PDF 표기. 서버·AI에 첨부가 없는지 검증.
5. 실제 Apple Watch+iPhone 한 조합과 Galaxy Watch+Android 한 조합으로 검증.

## MVP 완료 기준
- 두 플랫폼 실제 기록이 원본 건강 앱의 동일 기간/출처와 대응함. 실제 기종·OS·앱 버전과 오차/지연을 남김.
- 부분 권한/거부/무자료/시간 초과에도 원문 수동 준비표 사용 가능.
- 휴대폰/워치 이중 기록, 수면 단계 중첩, 자정 경계 및 시간대 변경 사례 검사.
- 앱 종료/동의 철회/조회 도중 화면 닫기 후 늦은 결과나 선택하지 않은 항목이 남지 않음.
- PDF에 선택한 요약·단위·측정 기간·출처만 표시. 미선택 요약과 원시기록은 없음.
- 서버·AI 네트워크 요청과 로그에 워치 원시값/요약이 없음.
- 시뮬레이터·가상 데이터 검사와 실제 기기 동기화 결과를 구분. 두 실기기 조합 전 연동 완료라고 발표하지 않음.

## 현재 구현과의 차이
현재 심박/SLEEP_ASLEEP 최근 24시간 숫자 기록 조회와 화면 전용 처리가 있다. 걸음 수, 단계별 수면 병합, 원본 기기 정보 보강, 결과 카드, 선택 요약의 로컬 준비표/PDF 전달은 새 구현이 필요하다. 이번 문서는 설계이며 실제 기기 검증을 수행한 기록이 아니다.
