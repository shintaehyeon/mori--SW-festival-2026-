# 모리 워치 연동 알고리즘·권한·동의 설계
작성일: 2026-10-28 KST. 개발 설계 및 시제품 상태이며 법적 적합성 인증 또는 실제 워치 연동 검증 결과가 아니다.

## 1. 최초 기획과 범위
최초 신청의 '기본 건강정보 및 일상 기록'을 보완하는 사용자 요청 확장이다. 웨어러블이 최초 제출 필수 기능이었다고 소급하지 않는다. 최우선 목적은 외국인의 지역 의료 이용·방문 이유 전달이며, 워치는 이를 위한 선택적 기록원이다. 워치가 없는 사람도 앱을 이용한다.

## 2. 플랫폼별 경로
- iOS: Apple Watch → iPhone의 Apple Health/HealthKit → Flutter health 플러그인 → 모리 화면.
- Android: Galaxy Watch → 스마트폰 Samsung Health → Health Connect → Flutter health 플러그인 → 모리 화면.
- Health Connect는 휴대전화의 데이터 저장/공유 계층이며 Wear OS 워치에 직접 설치해 조회하는 경로가 아니다.
- 워치 센서를 직접 실시간 구독하지 않는다. Apple/Samsung 동기화 간격과 누락에 영향을 받는다. 출처가 휴대전화/수동입력일 수 있으므로 모든 기록을 '워치 측정'으로 표시하지 않는다.
- 현재 health 13.3.2 사용. 웹은 미지원 안내만 제공한다.

## 3. 이번 구현 범위
- 상단 워치 버튼 → 목적·항목·보유·거부/철회 설명 → 수집·이용 선택 동의 → 별도 민감정보 처리 선택 동의 → 심박수/수면 선택 → OS 읽기 권한 → 최근 24시간 조회.
- READ만 요청. 심박수, SLEEP_ASLEEP 구간, 시각, 출처/기록 ID를 화면 메모리에서 처리.
- 원시 데이터 서버 저장/AI 전송/가족 자동 공유 없음. 이 화면 종료 시 상태 해제. 별도 사용자 계정이나 동의 이력을 서버에 생성하지 않음.
- 매번 화면을 다시 열면 다시 동의. 앱 내 동의는 OS 권한의 대체가 아니며 OS 허용도 앱 내 처리 동의의 대체가 아니다.
- 수동 조회만 구현. 자동 백그라운드 동기화, 정상/비정상 판정, 진료 카드 자동 편입은 미구현.

## 4. 상태 전이
UNSUPPORTED → 웹/지원하지 않는 OS: 안내, OS API 미호출.
IDLE → PURPOSE_SHOWN → COLLECTION_CONSENT + SENSITIVE_CONSENT → TYPES_SELECTED.
세 조건이 충족될 때만 REQUEST_OS_READ → READING → DATA_AVAILABLE / NO_READABLE_DATA / ERROR.
- authorize 반환 성공은 특히 iOS에서 읽기 허용 확정으로 해석하지 않는다.
- iOS는 읽기 거부와 자료 없음의 구별이 제한된다. NO_READABLE_DATA는 거부/미동기화/미기록/제한 조회를 함께 안내하며 거부라고 단정하지 않는다.
- clear/dispose 시 epoch 증가, 진행 중 작업 결과 무시, 화면 데이터 삭제, 다음 읽기 차단. OS 원본 삭제·OS 권한 철회와 구분한다.
- 앱 내 중단 버튼은 즉시 로컬 읽기를 중지한다. OS 권한 철회는 건강 앱/Health Connect에서 사용자 수행.

## 5. 읽기 알고리즘
1. 지원 플랫폼 검사. 미지원이면 API 호출하지 않음.
2. 동의 2개와 항목 선택 확인. 기본 체크 없음.
3. 선택 항목으로만 READ 권한 요청. 실패하면 재시도/OS 설정 안내.
4. now와 now-24h 범위 조회. 로컬 시각 표시, 비교에는 DateTime 타임스탬프 사용.
5. 숫자형 기록만 수용. NaN/무한/음수·역전 구간·조회 범위와 겹치지 않는 자료 제외.
6. 출처+항목+원본 ID로 중복 제거. ID가 없으면 출처+항목+시작+종료+값으로 제거.
7. 종료시각 최신순 정렬. 화면 메모리 최대 500개, 화면 표시 최신 20개. 원본 앱·측정시각과 마지막 조회시각 구분.
8. 수면 구간/중복 출처를 단순 합산하지 않음. 현재 일일 총수면·통합 심박 평균·개인 건강 점수는 계산하지 않음.
9. 데이터 없음은 0·정상·수면 0시간으로 채우지 않음. 부분 권한 또는 일부 실패도 완전 수집이라고 주장하지 않음.
10. 결과는 화면 전용. 워치 원시 기록에 서버 API 호출·커뮤니티 집계·AI 호출 경로 없음.

향후 총수면 계산 시: 출처 선택 → 수면 단계 중 실제 수면 단계만 선택 → 동일 출처 겹치는 구간 병합 → 구간 경계/시간대/서머타임 처리 → 원본 수면과 수동기록 별도. 여러 앱의 수면/걸음 수를 그냥 더하지 않음.
향후 장기 동기화 시: 동의 버전·항목·최종 cursor 저장, 겹치는 조회 창과 ID upsert, 원본 삭제/변경 반영, 권한 철회 후 재개 금지, 원본/파생 데이터 삭제 경로가 먼저 필요.

## 6. 요청하는 권한 / 요청하지 않는 권한
| OS | 요청 | 목적 |
|---|---|---|
| iOS | HealthKit entitlement, 심박/수면 읽기, NSHealthShareUsageDescription | 선택한 건강기록 표시 |
| Android | READ_HEART_RATE, READ_SLEEP, Health Connect 가용성 | 선택한 건강기록 표시 |

건강기록 쓰기, 위치, 연락처, 마이크, 카메라, 전화 발신 제어, 자동 SMS, Bluetooth 직접 스캔, 접근성 서비스, 휴대전화 전체 제어, 기기 관리자, 백그라운드 건강 데이터 읽기를 요청하지 않는다. 기존 tel/sms 링크는 사용자가 OS 화면에서 통화/전송하는 별개 기능이다.

Android는 FlutterFragmentActivity 및 Health Connect 권한 설명 Activity/Android 14 권한 사용 안내 alias를 설정했다. iOS는 HealthKit entitlement를 Runner 구성에 연결했다. 배포 인증서/프로비저닝 및 스토어 검토는 별도 필요.

## 7. 동의·처리방침 구조
건강정보를 동의 근거로 처리할 경우 일반 수집·이용과 민감정보 처리 동의를 분리하는 설계를 따른다. 건강 측정치를 개인 식별 목적의 생체인식 템플릿과 혼동하지 않는다.

화면에서 고지할 것: 처리 주체·목적·항목·보유기간·거부권·거부 영향·철회/삭제 방법·문의처. 이번 화면은 실제 화면 메모리 처리 범위를 설명하는 시제품이며 운영 주체/문의처를 확정한 최종 이용약관/처리방침이 아니다.

운영 전 확정 항목:
- 개인정보처리자 명칭·연락처, 공개 URL, 정책 언어·버전·시행일.
- 앱 내 별도 민감정보 동의와 항목별 OS 권한. 전체 동의에 끼워넣지 않음.
- 서버 보관 추가 시 저장 위치·기간·접근권한·암호화·삭제·백업 소멸·동의 증빙 설계.
- AI/클라우드 처리 추가 시 실제 수신자·처리 위탁/국외이전 해당 여부·보관정책 확인 후 필요한 고지/동의 적용. 현 UI의 로컬 처리 동의로 서버 전송하지 않음.
- 가족 공유는 수신자·데이터·기간·철회 범위를 별도로 설계. 학교/직장 접속 수에 건강 측정치 포함 금지.
- 만 14세 미만 지원 여부/법정대리인 절차, 민감정보 노출 방지, 계정/기기 공유·백업 위험 검토.
- Apple 건강정보 이용 조건/앱 개인정보 표시, Google Play Health 앱/Health Connect 권한 및 Data safety 신고를 실제 처리 범위와 일치시킴.

'동의했으니 모든 휴대전화 제어 허용' 같은 포괄 권한은 사용하지 않는다. 법률·스토어 적합성은 정책과 구현, 운영환경을 함께 검토해야 하며 체크박스만으로 완료되지 않는다.

## 8. 필수 검증
- 미동의/한쪽 동의/항목 미선택에서 요청 횟수 0.
- iPhone 실제 HealthKit 허용·거부·항목별 제한·무자료·기기 잠금·재설치.
- Galaxy Watch→Samsung Health→Health Connect 실제 데이터, 연결 지연·미설치·OS별 권한 설명 진입.
- 두 출처/중복 기록/기간 경계/빈 데이터/잘못된 숫자 처리.
- 조회 도중 동의 철회/화면 닫기: 이후 도착한 결과 표시 금지.
- 서버 네트워크/분석 로그에 건강 원시값이 없는지 확인.
- 실제 워치로 테스트 전 '연동 완료' 또는 실시간 모니터링 성공이라고 발표하지 않음.

## 구현 제약 보충
현재 수면은 플러그인의 SLEEP_ASLEEP 자료만 조회한다. Watch가 단계별 수면(SLEEP_LIGHT/DEEP/REM)으로만 기록하는 경우 전체 수면을 반영하지 못할 수 있다. 단계별 조회·정규화·구간 병합을 실제 기기에서 검증한 뒤 총수면 요약을 추가해야 한다. 앱 최소 iOS 15.0/Android API 26은 플러그인 빌드 요건이며 Health Connect가 모든 해당 기기에서 이용 가능하다는 뜻은 아니다.

최종 빌드 확인: 웹, iOS 시뮬레이터, Android debug APK 모두 성공. 자동검사 24개 통과. 실제 Watch→휴대전화 동기화 및 OS 권한 허용/거부/철회 실기기 검증은 아직 남아 있다.
